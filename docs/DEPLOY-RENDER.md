# Deploy the judges' demo on Render (free)

The hosted demo is one free Render web service that runs `payleash-proxy --demo` and serves the dashboard. It needs **no PayPal
keys, no database and no persistent disk**. PayPal is a recording; nothing in this process can reach PayPal (the server refuses to
start with a non-sandbox `PAYPAL_BASE_URL`, ignores sandbox credentials in demo mode, and blocks any outgoing request to a PayPal host).

## 1. Deploy

1. Push the repository to GitHub (public is fine; there are no secrets in it).
2. Go to https://dashboard.render.com, **New +**, **Blueprint**, connect the GitHub repository `bck-stack/payleash` and pick the branch (`main`).
   Render reads `render.yaml` and proposes one service, `payleash-demo`, plan **Free**. Click **Apply**.
   (Or use the *Deploy to Render* button in the README.)
3. Wait for the first build, about 3 to 5 minutes (`pnpm install`, `pnpm build`, dashboard build). The service gets an address like
   `https://payleash-demo.onrender.com` (the exact name depends on what is free).
4. Open it. The login page shows the **read-only demo** button for judges.

Without the blueprint (manual): **New +, Web Service**, runtime **Node**, plan **Free**, then

| Field | Value |
| --- | --- |
| Build command | `npm install -g pnpm@10.28.0 && pnpm install --frozen-lockfile --prod=false && pnpm build && pnpm build:dashboard` |
| Start command | `node packages/proxy/dist/bin.js --transport http --demo --host 0.0.0.0 --dashboard apps/dashboard/dist` |
| Health check path | `/healthz` |

## 2. Environment variables

`render.yaml` sets all of these. Only change them if you know why.

| Variable | Value | What it does |
| --- | --- | --- |
| `NODE_VERSION` | `22` | Node 22 |
| `PAYLEASH_OWNER_TOKEN` | generated by Render | **Your** dashboard login. Read it in the service's *Environment* tab. Never share it. |
| `PAYLEASH_DEMO_TOKEN` | `judge-demo-2026` | The public read-only demo passcode. |
| `PAYLEASH_DEMO_SHOW` | `1` | Shows the demo button (and passcode) on the login page. |
| `PAYLEASH_DEMO_NIGHTLY_RESET` | `1` | Wipes and re-seeds the demo every night. |
| `PAYLEASH_DEMO_RESET_HOUR_UTC` | `3` | The hour of that reset (03:00 UTC). |
| `PAYLEASH_TRUST_PROXY`, `PAYLEASH_COOKIE_SECURE` | `1` | Render terminates TLS: Secure cookie, real client IP for the login throttle. |
| `CF_ACCOUNT_ID`, `CF_API_TOKEN` | *(optional)* | Cloudflare Workers AI (free tier) for plain-language policies. Without them a rule-based parser answers. |
| `PAYLEASH_VAPID_*`, `RESEND_API_KEY`, `NOTIFY_EMAIL_TO` | *(optional)* | Phone push alerts and an email fallback for held calls. |

Do **not** add `PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET` to the hosted demo.

## 3. What a visitor can and cannot do

The demo account (`judge-demo-2026`) sees every page, can approve or deny the seeded demo calls (they run on recorded data), run the
backtest on the recorded 90-day history and change the what-if slider. It cannot freeze agents, sign mandates, subscribe to alerts or read
live PayPal data (there is none).

## 4. Free tier: it sleeps, and how to keep it awake until 15 December 2026

A free Render web service **spins down after 15 minutes without traffic** and takes about 30 seconds to start again. The login page says
so ("first load may take about 30 seconds"). To keep it awake for the judges:

1. **Uptime check (included).** `.github/workflows/demo-uptime.yml` calls the demo every 10 minutes (`scripts/uptime/check.mjs`) and turns red
   if it is unhealthy. In the GitHub repository: *Settings, Secrets and variables, Actions, Variables, New repository variable*,
   name `DEMO_URL`, value `https://<your-service>.onrender.com`. GitHub pauses scheduled workflows after 60 days without repository activity:
   push anything now and then, or run the workflow by hand (*Actions, Demo uptime, Run workflow*).
2. **Or an external monitor**, for example a free UptimeRobot HTTP monitor on `https://<your-service>.onrender.com/healthz` every 5 minutes.
3. Free instances have a monthly allowance of 750 hours, which covers one service running all month. Do not run a second free service in the same account.

Check by hand at any time:

```bash
pnpm demo:check -- https://<your-service>.onrender.com        # exit code 0 = healthy
curl -s https://<your-service>.onrender.com/healthz            # {"ok":true,"mode":"fixtures","demo":true,...,"reset":{"next":"...T03:00:00.000Z"}}
```

## 5. Nightly reset

At 03:00 UTC the process deletes everything visitors did (approvals, audit log, budgets, freezes) and seeds the demo again: two agents, one
automatic decision, five held calls, two denials, fresh dates. Mandates are re-issued for 30 days, so the dashboard never shows an expired
mandate. `/healthz` shows `reset.last` and `reset.next`. A *Reset the demo* button on the Overview page does a softer re-seed on demand. If the
service restarts for any reason (Render redeploys, sleep) it starts from the seed anyway: the demo has no state worth keeping.

## 6. Troubleshooting

* **Build fails on `pnpm`:** the build command installs the pinned pnpm itself; check the build log for the first error.
* **Health check fails after deploy:** open the *Logs* tab. `payleash-proxy` must print `DEMO MODE:`. A PayPal variable that points at a non-sandbox URL stops it from starting (on purpose): remove it.
* **Blank page / old page after an update:** hard-reload. The dashboard is a PWA and caches its shell.
